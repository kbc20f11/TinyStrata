# RTX 3060 12 GB Ampere follow-up

The tests ran on Windows on an RTX 3060 12 GB (SM86), driver 610.88, CUDA compiler 13.2.86 and a Ryzen 9 7945HX3D. The starting revision was `f3c29b1`. This is the existing five-model lineup. The one-start baseline and the paired development runs are diagnostic measurements under the v2 workload. They do not replace a four-start standard benchmark.

Qwen and Tiel now check free dedicated VRAM against the existing reserve before shrinking the Expert cache for temporary staging on Windows SM86. The control reproduced startup or later cache restoration failures. Checking first retained more Experts in the low-headroom comparisons. These comparisons also recorded differences in some captured output. A loan that starts above the reserve can still fall back if available memory drops during the loan.

Clover reuses the existing INT8 shared-head kernel for eligible eager causal single-row decoding from an 8K prefix on SM86. The fixed-cap comparison matched output and Expert geometry, and the CUDA kernel parity suite passed 27 cases. Prefill speed was effectively unchanged. One automatic-placement pair differed in output after 16K while the engine reported a different number of resident Experts.

LFM's mapped row-table upload follows PolyStrata's approach. Both 4K runs improved by 2.5–2.8% with matching outputs and little change at 16K. The separate 512-row scratch reuse test recovered 52 MiB, matched outputs at fixed Expert placement and held throughput. A larger prompt chunk keeps the same model weights and KV format, but can change routing arithmetic and Expert placement. The isolated 512-row screen measured −0.9% on short generation and was preferable to the −9.9% observed with 1024 rows. [PolyStrata row-table transfer](https://github.com/simplexai-labs/PolyStrata/commit/f0ab63a90) · [PolyStrata LFM chunk comparison](https://github.com/simplexai-labs/PolyStrata/commit/36fdc62ed)

The combined LFM screen measured 4K input at 1568.51 → 2159.65 tok/s and 16K input at 1444.76 → 1861.35 tok/s. The 32-token request completion times fell by 23.8% and 21.4%. The separate short code generation case fell from 117.46 to 112.10 tok/s. Managed auto selects 512 only for the measured Windows SM86 12 GiB profile with at least 10 GiB of confirmed dedicated headroom before load. An explicit chunk still controls the setting.

An additional one-start v2 run with the final managed LFM defaults measured 121.08 tok/s generation, 2163.08 tok/s for 4K and 1842.35 tok/s for 16K. The engine reported a 512-row chunk, shared FFN workspace and 152 mapped row-table uploads. The one-start generation result varies across runs and includes several prompts. The paired short code case above measures the tradeoff for that prompt.

## Other candidates

- An extra 32 MiB for staging did not prevent Qwen cache restoration failures. One staging buffer sometimes reduced memory pressure, but Tiel's 16K input throughput dropped 3.5%. Qwen's compact CPU Expert merge had no dependable gain.
- Gemma's mapped table upload did not improve input speed. The CPU worker change also regressed generation when Expert placement was fixed. The same worker change on LFM had no gain.
- Clover's paired Q8 projection path produced matching outputs. Its apparent gain after 4K disappeared in the reversed comparison.

## API workflow checks on the final build

Qwen, Clover and Tiel extracted all nine expected facts from synthetic Japanese shipping records at 34K input tokens, then answered a follow-up from the cached prefix. Each returned HTTP 400 for context overflow and answered the next valid request in the same model process. They read the first image label, rejected a malformed image, then read a different label after receiving a replacement image with the same dimensions.

LFM always uses reasoning. With a 2,048-token output limit, the original LFM consumed the budget before giving a final answer to the nine-field request. The final build answered with eight exact fields and omitted the requested `JST` suffix from the otherwise correct deadline. A separate three-field prompt also exhausted the 2,048-token budget before answering, so the LFM long-document follow-up remains unverified. Its context-overflow recovery check passed.

## Reduced VRAM headroom

A separate CUDA allocation held 4 GiB on the same RTX 3060. NVML reported 7.28 GiB free before model load. The physical card and its reported total capacity were 12 GiB throughout.

LFM managed auto selected 256 rows and matched the explicit 256-row run's outputs, native work and Expert allocation. Qwen with the staging check improved short generation from 69.03 to 73.06 tok/s, 4K input from 220.44 to 258.47 tok/s and 16K input from 281.04 to 331.95 tok/s. Expert placement and some generated text differed in that Qwen comparison.

Clover's 16K generation improved from 25.81 to 40.91 tok/s with matching output and different Expert placement. The fixed-placement pair above isolates the kernel change more closely. All three reduced-headroom comparisons completed and unloaded normally.
