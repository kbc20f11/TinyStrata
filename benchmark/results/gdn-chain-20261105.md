# Clover GDN chain measurements — 2026-11-05

## English

Clover's eligible GDN sequence now shares one cooperative CUDA launch: qkv/z and alpha/beta projections, convolution and normalization, recurrence, activation quantization, and the output projection. The selected schedule retains the existing arithmetic and its FP32 rounding boundaries. Automatic use is limited to qualifying Clover raw-Q8 execution on Blackwell; Qwen keeps its existing default path.

These are controlled development comparisons, **not standard tinystrata-bench-v1 results**. They supplement the [earlier Basalt-inspired CPU/checkpoint work](basalt-adoption-20261105.md#english) and leave every historical README benchmark table unchanged. Small repeated point estimates are not statistical-significance or cross-machine guarantees.

### Clover FP8: repeated all-GPU comparison

Candidate 5 is compared with the frozen baseline in **eight fresh API starts**, one **A1/B1/B2/A2** sequence followed by **B1/A1/A2/B2**. Each start measures the three [benchmark generation prompts](../cases.json) three times, capped at 256 output tokens, then exact 4,096- and 16,384-token inputs capped at 128: **88 measured requests** in total, excluding identical warm-ups.

Both sides use temperature **0**, seed 1234, thinking enabled, the remaining fixed benchmark sampling parameters, `strata_checkpoint:false`, zero prefix reuse and complete input reads. Clover is **causal D0 / MTP0**, FP8 MMA KV, context **262,144**, automatic chunk selecting **512**, with the GPU image encoder resident. All **10,240 / 10,240 Experts** stay on GPU, **13,246,464,000 payload bytes**, matching at every start and completion. B explicitly enables the diagnostic chain with a 70-CTA grid; A uses the frozen executable.

Generated throughput is the sum of final generated tokens, including thinking, divided by native decode time. Speculative proposals are not output tokens. Percentages use unrounded pooled counts/times.

| Decode workload | Frozen baseline | Full GDN chain | Change |
|---|---:|---:|---:|
| Short-prompt group, 36 requests/arm | 93.641407 tok/s | 95.217825 tok/s | +1.683% |
| After 4K input, four requests/arm | 92.030054 tok/s | 93.580933 tok/s | +1.685% |
| After 16K input, four requests/arm | 89.821410 tok/s | 91.325830 tok/s | +1.675% |

| Input processing | Frozen baseline | Full GDN chain | Change |
|---|---:|---:|---:|
| Short-prompt group | 2,094.741235 tok/s | 2,088.117823 tok/s | -0.316% |
| 4K | 2,280.941111 tok/s | 2,280.115787 tok/s | -0.036% |
| 16K | 2,034.571826 tok/s | 2,034.445507 tok/s | -0.006% |

Short decode has **9,216 final tokens/arm**, with 98,418.0 ms baseline versus 96,788.6 ms candidate decode time. The first order's decode changes are **+1.279% / +1.432% / +1.307%**, the reverse order's **+2.088% / +1.937% / +2.042%**, for short / after 4K / after 16K. The positive direction repeats, but per-start variation remains: the first order's baseline short rates range from 95.089 to 93.152 tok/s. **No prefill improvement is claimed.**

All corresponding request bodies, independently recomputed answer/reasoning hashes and native generated/prompt/read/reused/offered/accepted counts agree across all eight starts. These text hashes do **not** by themselves establish identity of raw native token arrays or full-model logits.

### Final automatic path: Clover INT8 with a fixed hybrid budget

The final candidate-7 executable is compared directly with the frozen baseline in **four fresh A1/B1/B2/A2 starts**. Each measures three short prompts capped at 128 plus exact 4K/16K inputs capped at 32: **20 requests** total. Temperature 0, thinking, context 262,144 and the one-shot/no-reuse policy match the earlier protocol; KV is **INT8**, chunk selects **2,048**, Clover stays causal D0/MTP0, and GPU Vision is resident.

Both builds receive a manual **4-GiB Expert budget**. Actual allocation is **2,760 / 10,240 GPU Experts, 3,570,336,000 payload bytes**, CPU workers **15 / 16 total threads**, identical at every startup/end. The only diagnostic environment setting is the same `STRATA_IQ_MT_MIN=1` on both sides. **No GDN enable override is passed**: B activates the final automatic policy and reports 30 eligible layers with actual host dispatches; the baseline has no full-chain path.

### Search history and rejected variants

The first cooperative prototype failed exact convolution output because the compiler contracted the expression differently. The fix matches the existing fast-math operation order explicitly: `mul(w1,v1)`, then `fma(w0,v0)`, `fma(w2,v2)`, `fma(w3,x)`. The first passing full-chain version was nevertheless flat in a 20-request Clover ABBA test: short **-0.047%**, after 4K **-0.286%**, after 16K **0.000%**.

Subsequent changes retain FP32 store/reload rounding while combining recurrence with quantization, then give each head its projections and local convolution, then use extra CTAs for alpha/beta. Saved implementations reduce grid-wide barriers **4 → 3 → 2 → 2**. The selected schedule uses 64 logical head jobs and, on this 70-SM device, the remaining six CTAs for alpha/beta. Fewer barriers alone did not establish a model-level gain; each version was measured.

Two additional screens were rejected:

| Screen | Frozen baseline | Enabled | Change / scope |
|---|---:|---:|---|
| Clover Q8-wide output only | 94.723599 tok/s | 92.060942 tok/s | -2.811%; one enabled start |
| Clover full chain plus Q8-wide | 94.723599 tok/s | 95.247544 tok/s | +0.553%; one enabled start |
| Qwen INT8 / MTP3 full chain | 145.327934 tok/s | 143.272890 tok/s | -1.414%; one enabled start |

The Clover screen has 12 short requests, three per start, with baseline A1/A2 bracketing the two enabled modes. Wide-only and combined paths report actual host dispatches. The screen supplies no reason to add wide to the simpler schedule with the repeated result above; it is not a controlled head-to-head estimate against that separate 88-request dataset. **The wide implementation, flag and INFO fields were removed.**

The Qwen screen has nine short requests in A1/B1/A2 order, capped at 128. It retains **real automatic interleaved MMVQ in every arm**, all **10,496 Experts / 12,238,413,824 bytes** on GPU, INT8 KV, MTP3, context 262,144 and chunk 2,048. The chain is active on 30 layers in B. Outputs and native prompt/generated/draft counts match. This screen shows no improvement, so **Qwen is not automatically switched**.

### Correctness evidence and microbenchmark limits

The full-chain tests compare all intermediate/output buffers, convolution history and SSM state with the existing kernels. Buffers are poisoned before eager and Graph replay comparisons. Verify mode must leave history/state unchanged; selected-prefix commit and T=4 causal execution are checked against sequential T=1. The passing gates include **112**, **136**, **160** and **132** checks for successive harness/prototype revisions; the first 112 did not cover interleaved Q6. The later revisions include **24 partial-IL comparisons**, matching the real Q6 qkv/z IL support with native output fallback.

The corrected-reference candidate-6 gate passes **148 checks**, including 16 standalone wide-output checks for the subsequently rejected experiment. The counts are from different harness revisions and must not be added as unique cases. The sampled independent CPU projection-dot oracle reports maximum absolute error **2.89952141e-7**; that is a sampled dot-product figure, not a full-model logit error bound.

Earlier Q8 microtimings labelled `Q8pair+Q8rows` used an optimized output-projection **stand-in**, not the actual engine baseline: the 4,096-wide output exceeds the `q8_small` limit and uses native MMVQ. The corrected timing reference is `Q8pair+native_out`. Kernel correctness used the native reference, and the baseline-executable end-to-end results above are unaffected. The 96-MiB cache-conditioning buffer used in later microtests does not prove complete L2 eviction. Warm-cache and conditioned microbench timings are not substituted for model throughput here.

```powershell
.\build-cuda\q36_gdn_chain_test.exe
```

### Final model, state and image regressions

- **Forced full-model logits:** final candidate 7 matches the frozen baseline in all four **Qwen/Clover × INT8/FP8** cases. A fixed 32-token prompt and 16 forced continuation IDs produce 17 rows of 248,320 FP32 logits per case: **16,885,760 FP32 word comparisons** in total, all finite, with **zero differing words**, identical raw-byte SHA-256 and matching greedy IDs. These tests use all-GPU Experts, context 32,768, chunk 512, MTP0 and no images. GDN is explicitly enabled for this numerical diagnostic, including Qwen; separate owned native preflights verify activation on 30 layers. This does not change Qwen's automatic policy or establish broad language-quality improvement.
- **Cancellation/checkpoint state:** the final executable passes **31 native cases**: 11 Qwen INT8, 11 Qwen FP8 and nine Clover FP8 causal-D0 cases. Fixed 4-GiB hybrid budgets, context 32,768 and chunk 512 exercise partial-input cancellation, committed-prefix retention, cold/resumed token identity and edited/unrelated-prefix restoration. Qwen uses MTP3 with synthetic image-boundary cases; Clover uses MTP0 without images in this suite.
- **Real images:** four fresh baseline/candidate API/encoder starts make **eight requests** with [the benchmark image](../image.png), FP8, context 32,768 and all Experts on GPU. Qwen uses MTP3 and its existing automatic route; Clover uses causal D0 with automatic GDN on the candidate. Answer/reasoning hashes and native counts match, encoder process identities stay stable and Expert allocations remain unchanged. Manual review confirms the red A square, blue B circle and green C triangle; Clover reads the title/subtitle correctly. Qwen preserves its baseline error, reading `LOCAL AI - 3 SHAPES` as `Logical – 3 Shapes`. This is no observed regression on the fixture, **not perfect OCR or general vision-quality validation**.
- **Optional D3 exact:** six short Clover native requests, three fixtures per build, retain matching raw token IDs and generated/prompt/reuse/resume/accepted/offered/finish counts with positive draft activity, using FP8, context 32,768, chunk 512, all Experts on GPU and no Vision; this is a limited regression smoke check, **not a quality or speed benchmark**.
- **Portability:** the touched engine compiles for CUDA **SM86** and HIP **gfx1200**. These are compile-only checks; Ampere/Radeon runtime behavior and speed were not measured.

### Eligibility and scope

Automatic activation requires **Clover, raw Q8_0 projections, CUDA compute-capability major 12**, the supported dimensions and T=1..4, plus successful cooperative-launch preparation. Packed Q8, unsupported dimensions/batches, preview/debug paths, HIP and other NVIDIA generations retain the existing route. Preparation probes only the weight type actually requested; unsupported capability or optional preparation allocation failure falls back to the existing path.

`TINYSTRATA_Q36_GDN_CHAIN=0` selects the legacy route. Explicit `1` permits supported diagnostic use, including Qwen Q6, for investigation; it does not establish a performance recommendation. `q36_gdn_chain_dispatches` counts host enqueue/capture calls, including warm-up, **not CUDA Graph GPU replay executions**.

These measurements do not establish gains on Radeon/Ampere or the separate Gemma/LFM drivers. Completed controllers preserve all four installed profile hashes and restore Clover causal D0/FP8/Vision/context 262,144. Raw outputs, temporary configurations, helpers and binaries remain outside Git; UI history and search/tool settings are not replaced.

## 日本語

CloverのGDN処理を、投影・畳み込み・再帰状態更新・量子化・出力投影まで一つの協調CUDA起動にまとめました。既存の演算順序とFP32丸めの境界を保ち、自動適用は**Blackwell上の対応するClover raw-Q8経路**に限定します。Qwenの既定経路は維持します。

**標準v1の再測定ではなく、既存README表も置き換えません。** 70 WのRTX PRO 4000 Blackwell SFFで、Clover因果D0・FP8・全10,240 Expert常駐をABBAとBAABの計8起動・88要求で比較しました。合算の生成速度は短文 **+1.683%**、4K入力後 **+1.685%**、16K入力後 **+1.675%** です。計測候補5と最終候補7の区別、KV・chunk・出力上限などの条件は上記に記載しています。

最終候補7の自動判定も、INT8・Expert予算4 GiB固定で別に4起動・20要求を確認しました。実配置は2,760個／3,570,336,000 bytes、CPUは15 worker＋呼出側で、旧版と一致します。GDN有効化の環境変数を渡さず、短文 **+3.027%**、4K後 **+4.890%**、16K後 **+3.387%** でした。FP8全常駐の88要求とは別条件なので、両者を合算したり同じ条件の速度差と扱ったりしません。

全88要求と別条件の20要求について、同じ入力への回答・思考テキストのハッシュと生成・入力・投機数は一致しました。テキストハッシュだけで生のトークン配列や全logitsの一致を証明したとは扱いません。入力処理の改善は確認できず、小さな速度差には起動間のばらつきが残ります。統計的有意差や他機種の高速化を保証する結果ではありません。

別の数値回帰試験では、Qwen／Clover×INT8／FP8の4条件で各17行・248,320語彙の強制継続logitsを比較し、**計16,885,760個のFP32値がすべて有限かつビット単位で一致、差分0**でした。この診断は全Expert GPU常駐・MTP0で、QwenもGDNを明示的に有効にしています。自動適用の対象はCloverのままです。最終版のキャンセル・チェックポイントは計31ケース、実画像は旧版／新版・両モデルで計8要求を確認しました。実画像の回答・思考と生成数などは一致し、Qwenの見出しの読み違いも旧版と同じです。OCR全般の正確さを保証する結果ではありません。任意のD3 exactも短い6要求で生の出力IDと投機数などの一致を確認しましたが、品質・速度のベンチではありません。SM86／HIP gfx1200はコンパイルのみ確認し、実機の動作・速度は未測定です。

初期版は演算順序の違いで失敗し、修正後も最初の実モデル計測は横ばいでした。同期削減と仕事の割り当てを繰り返して上記の結果に至っています。独立したQ8-wide経路は単独で **-2.811%** のため除去しました。Qwen MTP3も実際のIL経路を維持した選別試験で **-1.414%** だったため、自動適用しません。

旧Q8マイクロベンチの一部は実エンジンと異なる出力投影を使っていたため区別し、修正した基準を使います。実際の旧版exeとの比較値には影響しません。未対応形状・packed Q8・HIP・他世代などは既存経路に戻し、対応確認や任意の準備用確保に失敗した場合もフォールバックします。GPU常駐率、保存済み設定、Cloverへの復帰は確認済みで、AMD・Ampere実機やGemma/LFMの高速化を示す結果ではありません。
