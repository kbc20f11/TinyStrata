# Measured speed — AMD Radeon RX 9070 XT (HIP)

Measured on **2026-11-04** using Windows 11 (build 26300), a Radeon RX 9070 XT (gfx1201, 16 GB; driver 32.0.32015.7029), a Ryzen 9 7945HX3D and 96 GB of system RAM, with the same model files as in the main [README](../../README.md). INT8 KV and VMM growth with a 4 MiB allocation quantum were enabled. Context capacity, input chunks and Expert placement were automatic. Qwen and Gemma used MTP 3 and a GPU-resident image encoder; LFM and the standard Clover row use neither.

Protocol: [tinystrata-bench-v1](../README.md#english), engine code [358043c](https://github.com/kbc20f11/TinyStrata/commit/358043c3749f5c6da36c749c98201c82b9c57a72), seed 1234, four independent API starts per model. The engines were built with the AMD HIP SDK 7.2.3 and ran on the HIP runtime installed with the display driver (`C:\Windows\System32\amdhip64_7.dll`, 10.0.3683.0).

Clover's context capacity here was chosen automatically.

## Measurement conditions

- The PC was restarted before these runs. Discord was assigned to the integrated GPU in the Windows graphics settings, and no other heavy application was running: about 1.7 GiB of VRAM was in use and 16–24% CPU utility was measured before each run.
- Run-to-run spread on the same PC and day, with builds that differ only in the diagnostics of PR #8: Qwen 89–103 tok/s, Gemma 88–97 tok/s and LFM 103–105 tok/s in repeated generation measurements. Differences of up to about 10% between single runs are within that spread.
- Speed also depends on the state of the PC: VRAM held by other applications reduces the resident Expert cache, and other work on the CPU can lower generation speed for the models that exchange data with the host every layer. See issue #7 for a longer discussion.
- These numbers come from one PC, one run set per row; use them as a reference for what a RX 9070 XT can reach, not as a guarantee.
