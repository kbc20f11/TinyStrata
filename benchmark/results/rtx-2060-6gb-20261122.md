# Measured speed on GeForce RTX 2060 6 GB (CUDA)

Measured on 2026-11-22 on an Intel NUC11PHi7 with an NVIDIA GeForce RTX 2060 (6,144 MiB, compute capability 7.5, driver 621.24), an Intel Core i7-1165G7 (4 cores, 8 threads), 32 GiB of DDR4-3200, and Windows 11 Pro build 26300. The monitor was connected through Thunderbolt USB-C to the Intel Iris Xe. The RTX 2060 reported its display output disabled.

The Windows API installer rebuilt commit [`85f5951`](https://github.com/kbc20f11/TinyStrata/commit/85f5951c4eedfa5fa6a3349751c759b21104727f) with its private CUDA 13.2.2 toolkit (nvcc 13.2.86). With the display on Iris Xe, the normal Qwen API reported `loaded: true` and `images: true` using the default CUDA configuration.

## Standard v1

The [official runner](../README.md#english) used four independent starts per model, seed 1234, INT8 KV with growth enabled, and automatic context, chunk size and Expert placement. Gemma used MTP 3 and GPU Vision. LFM and standard causal Clover used text only. Rates pool native token counts and times. Image timings show the median time to first output and completion, including image encoding.

Each complete row includes 24 timed generation requests and four fresh requests at each input length. All three models selected a 65,536-token context. Prompt chunks were 1,120 for Gemma, 256 for LFM and 512 for Clover.

## Qwen and Tiel retest after the Turing scratch fix

Both models completed the 16K input, 32-token continuation and image case after rebuilding commit [`45ed1f6`](https://github.com/kbc20f11/TinyStrata/commit/45ed1f69802327e4caeb44e34878126e893b00e6). The KV cache grew from 16,384 to 24,576 rows, with 308 MiB physically committed after the expansion. Both models used INT8 KV, MTP 3, a 65,536-token context, a 512-token prompt chunk and GPU Vision.

## Saved profiles after the API installer update

On the same machine, `install.ps1` from [`75e29e0`](https://github.com/kbc20f11/TinyStrata/commit/75e29e0394bae9f19f507eab498813e0c8028864) detected the running Qwen API and updated it without `-Rebuild` or `-Update`. It built a fresh CUDA generation because validation of the previous build's dependency record was incomplete. The API restarted with the already installed Qwen and GPU image encoder. No model files were downloaded during the update.

Each model ran separately with `--saved-profile --runs 1` under `tinystrata-bench-v1-saved-profile` (`standard: false`). The runner used private copies of the saved profiles with the updated executable and library paths. The profiles retained their saved sampling, engine and Vision options. The same benchmark inputs were used, with three timed generation requests and one request at each input length per completed start.

Clover's image encoder loaded and warmed up at 4,096 image tokens. Its language engine then needed 200 MiB of new backing for the initial 16,384 KV rows and reported 0 MiB available for that allocation. The engine exited with code 1 before any benchmark cases ran. The text-only standard v1 results above were measured separately.

## Earlier incomplete runs on `85f5951`

- **Qwen3.6 UD-IQ3_XXS, standard v1.** Both attempts passed warm-up, the six generation cases and the 4K input case on the first start. The 16K input case then needed 88 MiB of new backing to grow KV from 16,384 to 24,576 rows. The engine reported 40 MiB available on the first attempt and 26 MiB on the retry, then exited with code 1.
- **Tiel Coder UD-IQ3_XXS, saved-profile variant.** Both attempts used MTP 3 and GPU Vision and selected INT8 KV. Each reached the 16K input case after three generation cases and the 4K input case. Each needed the same 88 MiB expansion, reported 41 MiB available, and exited with code 1. This is the runner's `tinystrata-bench-v1-saved-profile` protocol (`standard: false`).

All five model downloads were verified. The LFM revision pinned by this TinyStrata commit returned HTTP 404. The [LiquidAI file at `f97fc8a`](https://huggingface.co/LiquidAI/LFM2.5-24B-A2B-GGUF/blob/f97fc8a443da86c71818adf91baecde5b7ef4c50/LFM2.5-24B-A2B-Q4_K_M.gguf) matched the pinned size of 14,526,258,464 bytes and SHA-256 `d3334405b96228eb9908cdebb5c6194908f2da64282bda852afc3a3910c64e7d`. The existing API accepted the local file after verifying it.
